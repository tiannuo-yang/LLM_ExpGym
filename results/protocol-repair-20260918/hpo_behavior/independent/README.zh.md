## 可评分不是有效配置提交

全部 486 条中，475 条有历史协议完整分数，11 条 DeepSeek 因缺少配置保持不可评分，没有填补零分。475 条中包含 77 条 `best_evaluated_fallback`；非回退计分终答为 398 条，其中只有 396 条可以直接解析为 JSON 对象。JSON 对象本身仍不证明满足配置 schema 或形成有效架构。

3 个历史零分样本均为 DeepSeek，其含义不同：

| slot_id | 条件 | 零分来源 |
|---|---|---|
| `3e3dc1bbb05a0b2fb57e1299` | NAS101-A Free | 模型输出 `I.`；历史离线终答评分将不可解析的非空文本计为零 |
| `e49629a3ed66653d979389f9` | NAS101-A Moderate | 模型输出准备开始评估的自然语言；历史离线终答评分为零 |
| `6c4fcbf467ffbc354381df55` | NAS101-B Moderate | 回退到已评估的无效图配置；可见工具性能为零 |

所以，`score_complete` 仅说明历史协议产生了可用的最终分数，不能描述为“模型成功提交有效配置比例”。修复后的正式评分需要在这些历史列旁独立给出；本复核只确认观察到的行为与既有评分来源，不冒充新的评分协议结果。

本目录路径根由脚本位置推导，复核目标为同一工作区的 `LLM_ExpGym-protocol-repair-20260918` 与完整私有存档。公开用户可使用上级目录的参数化主脚本或 `verify_public_behavior.py` 复算；公开 CSV 复算和读取原始轨迹的独立复核是两个不同证据层级。
