# Search trajectory：反馈收紧改变的是可获得的信息，而不只是调用次数

分析覆盖当前主报告的全部 1,314 条单 agent Search trajectory：6 个模型、73 道题、Free / Moderate / Tight 三种预算；没有抽取有利样本，也没有新增模型调用或重评分。每个模型—预算组合的已有 F1 均与冻结主报告一致（18 项，误差小于 1e-12）。以下都是描述性结果，不是因果分解。

## 1. Tight 把不同模型的探索广度压缩到相似的信息瓶颈

| 每次任务的平均量 / 终止比例 | Free | Moderate | Tight |
|---|---:|---:|---:|
| F1（0–100） | 61.12 | 50.68 | 17.29 |
| 已执行的 search 调用 | 15.45 | 10.67 | 4.13 |
| 模型实际收到的工具反馈 | 15.45 | 10.36 | 3.32 |
| 实际看到的不同文章 | 12.34 | 8.14 | 2.63 |
| 预算耗尽后强制提交 | 0 / 438 | 134 / 438 | 354 / 438 |
| 非强制最终回答 | 336 / 438 | 285 / 438 | 79 / 438 |

Free 下，不同模型平均看到 9.58–15.56 篇不同文章；Tight 下这个范围缩至 2.59–2.66，且每条 trajectory 都只获得 2 或 3 篇不同文章。这表明预算不仅让同一行为序列变短，也把模型置于一个共同、很窄的信息窗口。**Tight 能力更取决于在有限观察内选择与整合哪些信息；Free 下能够展开多少探索，并不能直接表征这种能力。** 当前数据不能把信息选择质量与后续推理质量进一步因果分离。

注意区分 acquisition attempt 和 received evidence：Tight 的 1,807 次已执行工具调用中，354 次结果由于越过预算被扣留；它们有反馈费用，但没有将文章交给模型。预算终止轨迹全部恰有一次这样的结果扣留及一次强制最终回答。不能把调用总数当作模型已经使用的证据量。

438 个模型—题目配对中，Free→Tight 的 F1 下降 252 项、相同 182 项、上升 4 项；相同包含两边都失败的情况，不能解释为预算无影响。6 个模型均表现为下降项远多于上升项。

## 2. 改写查询并不等于获得新的证据

Free 下 183 / 438 条轨迹至少一次返回已经看过的文章。6,567 次文章交付中有 1,160 次重复（17.7%）；其中 1,144 次（98.6%）使用了此前不同的 query 字符串，却仍命中同一篇文章。Moderate 为 824 / 832 次重复，Tight 为 266 / 268 次重复，模式一致。

这是一个跨预算的观察级冗余模式，而不只是复制同一条命令。**以 query 的不同数量衡量探索广度会夸大真实信息增量。** 在人工核查的代表性轨迹中，给人名追加亲属关系或属性词，仍会检索到刚读过的人物文章，而不是执行关系推断。这里不推断模型的内部意图；事实依据是实际 query 与返回文章的映射。

本场景已经对已返回文章免收再次检索的反馈费用，因此不能把这些重复解释成额外的有偿 acquisition。它们仍占用工具调用与决策步数。这个观察提示 future analysis 应同时记录 **action novelty** 与 **observation novelty**，并研究是否能在选取下一步动作前识别没有信息增量的候选动作。它是研究动机，不是已经验证的 PoolAct 因果解释。

## 3. 没有被系统打断，不代表任务已解决

Free 的 336 次非强制最终回答中，有 114 次 F1 不满分（33.9%），其中 59 次为零。与之相对，85 / 438 条轨迹用满步数或评估次数上限。两者表明失败有不同的可观察终止形态：未被迫停止却提交不完整或错误回答，以及持续尝试到达交互上限。不能从 terminal tag 推断信心、已覆盖所有分支或真正的停止原因。

模型的停止方式也不同。GPT 在 Free 下 71 / 73 次非强制结束，平均获得 9.58 篇不同文章、F1 为 64.01；Gemini 为 50 / 73 次、15.56 篇、F1 为 72.03。更多探索在此与更高整体 F1 同时出现，但不能据此给出“多调用必然更好”的策略建议，因为题目难度和路径选择均影响调用量与结果。

Tight 下 80.8% 的任务是预算终止；剩余 79 次非强制结束也平均已消耗 98.34% 的预算。因此，Tight 的主导现象不是普遍闲置大量预算，而是大多数轨迹接近或越过 acquisition 边界后提交答案。

## 证据与边界

- [by_model_regime.csv](by_model_regime.csv)、[overall_regime.csv](overall_regime.csv)：上述结果与终止分布；`natural_stop` 仅指没有 forced final 的正常最终回答。
- [paired_direction_summary.csv](paired_direction_summary.csv)：Free→Tight 配对方向；逐项配对在 [free_tight_paired.csv](free_tight_paired.csv)。
- [trajectory_metrics.csv](trajectory_metrics.csv)：1,314 条原始 trajectory 的路径、SHA256 与只读派生标量。`attempted_feedback` 指框架实际执行的 search 调用，不包括被协议拒绝、未执行的函数请求。
- `paid_feedback_calls` 只计 `simulated_cost_seconds > 0` 的工具调用，包括无总额上限的 Free；它不是实际运行时长、API 支出或金钱成本。`feedback_charge_seconds` 同样是任务定义的模拟费用。
- [representative_case_index.csv](representative_case_index.csv)：12 个有明确选择规则的代表性原始轨迹入口。逐模型选取 Tight 预算终止且未满分、以及 Free 非强制结束且未满分两类中，不同文章数的上中位数样本；仅用于核查可观察机制，不据此估计其总体频率。已检查工具 query、返回文章、可见性、终止通知和最终答案；没有将内部思考内容作为行为证据。
- [INPUTS.json](INPUTS.json)、[CHECKS.json](CHECKS.json)：输入身份及回归检查。Gemini 所选原始轨迹逐一匹配冻结源索引的 SHA256；其 Search N1 部分完整，未混入尚未完成的 HPO。
- [analyze_search.py](analyze_search.py)：复算入口。需要本地存档原始轨迹；输出默认写到脚本所在目录，不下载、恢复归档或调用模型。

Free 和 Tight 的 438 个配对全部先获得相同的第一篇文章，其中 274 对的 Tight 文章序列恰为 Free 序列前缀。这个配对事实只说明相当一部分轨迹在相同入口后被截短；独立生成、预算反馈与后续选择共同作用，不能把它视为人为截断 Free trajectory 的对照实验。

Search 每次新文章的模拟反馈费用约为 300 秒，Moderate / Tight 额度分别为 3,000 / 900 秒；Free 无反馈总额上限但仍有交互步数上限。这些是任务反馈费用单位，不是实际模型运行时长。其他终止原因保留在明细中，不将其伪装为预算终止。
